슬로건

“쌓으면, 보입니다.”는 편집이 한 번씩 쌓여서(리비전) 지식이 드러난다는 뜻입니다. 빈 문서 안내나 푸터 같은 화면 문구도 이 말투에 맞춰 씁니다.

나무위키의 기능, 구조, 문법 사양은 참고하지만 로고, 마스코트, CSS, 문서 본문은 가져오지 않습니다. 테스트용 문서도 직접 쓴 내용만 쓰고, 라이선스는 CC BY-NC-SA 2.0 KR 기준 문구를 따로 작성해 표시합니다.

PerMark

Percentage 문서를 쓰는 위키 문법입니다. 제목, 굵게와 기울임, 내부 링크, 각주, 표, 접기 블록, 목차, 틀 불러오기, 분류를 지원합니다.

== 개요 ==
[목차]
'''폰 노이만 구조'''는 명령어와 데이터를 같은 메모리에 두는 방식이다.[* 1945년 EDVAC 보고서 초안]

=== 등장 배경 ===
* [[ENIAC]]은 계산을 바꿀 때마다 배선을 다시 했다.
* 자세한 건 [[프로그램 내장 방식|이 문서]] 참고.

|| 기계 || 시기 ||
|| Manchester Baby || 1948 ||

{{{#!folding 여담
''이름''을 두고 논란이 있다.
}}}

[include(틀:컴퓨터 구조)]
[각주]
[[분류:컴퓨터 구조]]

파서가 알아듣는 요소는 이 밖에도 취소선, 인라인 코드, 코드 블록, 글자 크기와 색 블록, 파일 링크, 리다이렉트, 날짜·나이·D-day·루비·앵커·페이지 수 매크로가 있습니다.

직접 만든 이유

위키 문법은 마크다운과 규칙이 달라서 외부 마크다운 라이브러리를 쓰지 않고 렉서, 파서, 렌더러를 전부 직접 구현했습니다. 잘못 닫히거나 안 닫힌 서식은 에러를 내지 않고 원문 그대로 남깁니다.

작은 부분도 신경 썼습니다. 제목은 앞뒤 =의 개수가 정확히 같아야 인식하는데, 역참조 정규식 /^(={1,6})(.+?)\1\s*$/은 == 개요 = 같은 줄에서 여분의 =를 본문으로 삼켜 버립니다. 그래서 앞뒤 =를 따로 세서 비교합니다. [include(...)]도 한 줄 전체가 정확히 그 형태일 때만 틀 블록으로 펼칩니다.

마크다운 변환

이미 가진 노트나 README를 옮기기 쉽게 마크다운을 PerMark로 바꾸는 스크립트를 만들었습니다. 제목, 굵게·기울임·취소선, 인라인 코드, 링크, 이미지, 목록과 체크박스, 인용, 수평선, 코드 블록, GFM 표를 변환합니다.

bun run convert:md <입력.md> [출력파일]

데이터

ORM 없이 Supabase JS 클라이언트와 supabase gen types로 만든 타입을 씁니다. 문서 저장, 되돌리기, 이동처럼 여러 테이블을 함께 바꾸는 작업은 Postgres 함수나 트랜잭션으로 한 번에 처리합니다.
